## 1. What it is & where it runs

NMEA 2000 (IEC 61162-3) is the standard control network on boats. GPS, depth, wind,
engine, rudder, autopilot, tank levels, and AIS vessel-tracking all share one bus. It
runs on CAN (250 kbit/s) with an application layer of PGNs (Parameter Group Numbers),
each a defined message type. It is the marine sibling of the automotive CAN / J1939
world, and it shows up well beyond boats, in some industrial and agricultural rigs.

The single most important thing for a researcher: NMEA 2000 is an open, unauthenticated
bus. Like CANopen or EtherCAT, there is no authentication or encryption, and every node
trusts every frame. So the attack surface is a node's parser of the PGN messages other
nodes send, and the realistic actor is a malicious, compromised, or counterfeit device on
the bus (adjacent, `AV:A`). A chart-plotter or autopilot parsing a crafted PGN from a
rogue sensor is the threat model.

- **Transport:** CAN, 29-bit extended IDs. The CAN ID encodes priority, PGN, and source
  address.
- **Authentication:** none, and no encryption, by design, like other field buses.
- **Role:** every node is a parser of bus traffic; the receiver of a crafted PGN is the
  target.

## 2. Frame & PGN model: single-frame, fast-packet, and the count fields

A PGN's data is carried one of three ways, and the multi-frame paths are where the
length and count handling lives:

- **Single-frame:** PGN data of 8 bytes or fewer, fitting one CAN frame.
- **Fast-packet:** up to 223 bytes split across frames. The first frame carries a frame
  counter plus the declared total byte length, then 6 data bytes; continuation frames
  carry a rolling 5-bit frame counter plus 7 data bytes. The receiver reassembles them
  into one message. Note the arithmetic: 6 + 31*7 = 223 bytes, the exact fast-packet
  maximum. That number matters later.
- **ISO transport (TP):** larger multi-packet transfers (PGN 60416/60160).

The researcher's hooks are the declared total length in a fast-packet first frame, and
the element, satellite, and station counts inside PGN payloads (for example, "number of
satellites in view"). These are classic declared-count-vs-actual fields that drive loops
and array writes.

## 3. The fuzz surface, mapped to ttlappalainen/NMEA2000

[ttlappalainen/NMEA2000](https://github.com/ttlappalainen/NMEA2000) (MIT) is the de-facto
open-source N2K stack, embedded in a large range of marine devices and gateways. Three
layers make up the surface.

The PGN decoders in `src/N2kMessages.cpp` are the prime target: the
`bool ParseN2kPGN#####(const tN2kMsg&, ...)` family (position, COG/SOG, GNSS,
satellites-in-view 129540, AIS static and position reports, engine, and so on). The
count-driven ones (satellites, AIS lists) are the highest-value.

Beneath them sit the shared extractors in `src/N2kMsg.cpp`:
`GetByte / Get2ByteUInt / GetStr / GetVarStr / GetBuf / ...`, reading fields out of the
message at an advancing index. This is the length and bounds primitive, and the home of
the UCS-2 to UTF-8 string conversion.

The receive path is the reassembly in `tNMEA2000::SetN2kCANBufMsg` (NMEA2000.cpp), the
fast-packet / TP state machine that assembles CAN frames into a `tN2kMsg`: frame
ordering, slot management, and the declared-length handling.

In-process libFuzzer reaches all three. A `tN2kMsg` is a plain struct, so you feed it
crafted bytes and call the parsers; the reassembly can be driven by feeding a sequence of
CAN frames to a minimal `tNMEA2000` subclass. No CAN hardware is needed.

## 4. Known bug classes (the live corroboration)

ttlappalainen/NMEA2000 itself has no CVE and is not on OSS-Fuzz. But the PGN-parse class
is demonstrably live. A sibling N2K implementation, the driver in gpsd, took two 2026
CVEs that are exactly this surface:

- [CVE-2025-67268](https://nvd.nist.gov/vuln/detail/CVE-2025-67268): heap out-of-bounds
  write in PGN 129540 (satellites-in-view), where the satellite count from the wire was
  not checked against a fixed 184-entry array. The canonical
  declared-count-drives-an-array-write bug.
- CVE-2025-67269: integer underflow leading to a CPU-exhaustion DoS in a related parser.

So the right question for any N2K stack is whether each count-bearing PGN decoder bounds
the declared count before indexing or writing.

## 5. A robustness note: ttlappalainen is defensively written, and it holds up

I fuzzed this stack in-process under AddressSanitizer, UndefinedBehaviorSanitizer, and
MemorySanitizer, all three. That was possible because it is a self-contained C++ build
with no external archive, unlike some of my other targets. Two harnesses: one
auto-generated over all ~55 `ParseN2kPGN*` decoders, and one over the fast-packet
reassembly state machine. Both were anchor-validated by planting a bounds bug and
confirming the harness caught it.

The result was clean: hundreds of millions of executions, zero memory-safety crashes,
zero undefined behavior, zero uninitialized reads. The exact gpsd bug class is guarded
here: `ParseN2kPGN129540` checks `NumberOfSVs <= MaxSatelliteInfoCount` before indexing;
the extractors bound the read index against the message length; the string paths clamp
the declared length to the bytes remaining.

The fast-packet path is safe by protocol design, which is worth internalizing. A
fast-packet message maxes out at exactly 223 bytes (6 + 31*7), the message buffer is
`Data[223]`, and the reassembly copy is additionally length-bounded. A declared length
larger than the buffer simply never completes, because it cannot be filled, rather than
overflowing. The declared-length field looks like a classic over-read primitive, but the
geometry of the protocol closes it.

This is a robustness-negative of the same kind as CANopen, BACnet (post-fix), ADS, and
the EPICS stacks: a virgin implementation of a protocol whose bug class is live elsewhere,
that nonetheless turns out to be carefully bounded. The value is the methodology and the
mapped surface, not a CVE.

## 6. Defensive notes

- Treat the N2K bus as a trust domain. It is unauthenticated by design; a counterfeit or
  compromised device is the realistic adjacent attacker. Physical and segment control is
  the real mitigation.
- Supply chain: vet second-hand and no-name N2K devices. An untrusted node is an `AV:A`
  foothold on everything else on the bus.
- If you integrate a different N2K stack (not ttlappalainen), audit the count-bearing PGN
  decoders for the gpsd class (satellite, AIS, and station counts against fixed arrays).
  That bug was real in a sibling implementation.
