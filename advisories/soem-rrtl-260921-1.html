Overview

This advisory covers several security vulnerabilities in SOEM (Simple Open EtherCAT Master) versions up to and including 2.0.0. All vulnerabilities can be triggered by a malicious or compromised device on the same EtherCAT network.

Mitigation Steps

Upgrade to SOEM 2.0.1 or later. All vulnerabilities are fixed in that release. As an alternative measure and to enhance security, ensure that EtherCAT devices are not connected to public networks. Devices that are not accessible to attackers, such as those on isolated networks or protected by firewalls, are at significantly reduced risk.

Vulnerabilities

CVE-2026-70388 — Memory Corruption via Integer Underflow in Message Length Validation

SOEM version 2.0.0 and earlier contains vulnerabilities where a malicious device on the network can send specially crafted messages that cause the master to write data outside allocated memory boundaries. The software performs arithmetic on message length values without proper validation, allowing negative or extremely large values to bypass safety checks. This can corrupt memory and potentially allow an attacker to execute arbitrary code on the master system.
CVECVE-2026-70388
CWECWE-191 — Integer Underflow (Wrap or Wraparound)
CWECWE-195 — Signed to Unsigned Conversion Error
CWECWE-787 — Out-of-bounds Write

Affected Products

Fixed: CSAFPID-0002

Known Affected: CSAFPID-0001

Scores

  • CVSS 3.1: 8.8 (HIGH) — CVSS:3.1/AV:A/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H

Remediations

Vendor Fix: Upgrade to SOEM version 2.0.1 or later

Notes

Technical Details: The SoE, CoE, EoE and FoE message handlers computes a payload size by subtracting a fixed header size from the slave-supplied length field using signed arithmetic. When the slave reports a length smaller than the header, the result is a large negative number. The negative value is used in a memory copy, where it is treated as a huge positive size (approximately 2^63 bytes), writing far past the destination buffer.

Fix: A validation step was added inside the central mailbox receive function. It now checks every incoming message's length against the per-protocol minimum and against the physical mailbox size before handing the message to any parser. A message that fails either check is discarded.

CVE-2026-82943 — Out-of-Bounds Read via Unchecked Length Values

SOEM version 2.0.0 and earlier contains vulnerabilities where a malicious device can send messages that cause the master to read data from memory locations beyond the intended buffer. The software uses length values from device responses without validating them against actual buffer sizes. An attacker can exploit this to extract up to 64KB of sensitive information from the master's memory, including data from other processes or system operations.
CVECVE-2026-82943
CWECWE-125 — Out-of-bounds Read
CWECWE-195 — Signed to Unsigned Conversion Error
CWECWE-200 — Exposure of Sensitive Information to an Unauthorized Actor

Affected Products

Fixed: CSAFPID-0002

Known Affected: CSAFPID-0001

Scores

  • CVSS 3.1: 8.1 (HIGH) — CVSS:3.1/AV:A/AC:L/PR:N/UI:N/S:U/C:H/I:N/A:H

Remediations

Vendor Fix: Upgrade to SOEM version 2.0.1 or later

Notes

Technical Details: The FoE, SoE, and CoE message handlers used the slave-supplied length field as the source size for a memory copy, without checking that it fits within the actual received buffer (which is at most 1487 bytes). A slave that claims a large length while sending a short message causes the copy to read past the buffer boundary into adjacent memory, which is then returned to the caller as data. A separate bug in the SoE handler caused an unassigned internal pointer to be used as the copy source after the receive completed, reading from near address zero.

Fix: The central mailbox receive validation (added for CVE-2026-70388) also limits the slave-supplied length to the physical mailbox capacity, so derived copy sizes are bounded by the actual buffer. The stale pointer issue was fixed by computing the source pointer after the receive returns (patch provided by Sankalp Thakur).

CVE-2026-82946 — Null Pointer Dereference in Mailbox Error Handling

SOEM version 2.0.0 and earlier contains a vulnerability where a malicious device can crash the master system. When the software receives an error response, it clears an internal pointer but continues processing. If another message arrives before timeout, the software attempts to use the cleared pointer, causing a crash. An attacker can trigger this with a simple sequence of two messages.
CVECVE-2026-82946
CWECWE-476 — NULL Pointer Dereference
CWECWE-690 — Unchecked Return Value to NULL Pointer Dereference

Affected Products

Fixed: CSAFPID-0002

Known Affected: CSAFPID-0001

Scores

  • CVSS 3.1: 6.5 (MEDIUM) — CVSS:3.1/AV:A/AC:L/PR:N/UI:N/S:U/C:N/I:N/A:H

Remediations

Vendor Fix: Upgrade to SOEM version 2.0.1 or later

Notes

Technical Details: When the mailbox receive function gets an error-typed response, it frees the internal buffer and clears the pointer to NULL. The retry loop then continued without acquiring a new buffer first. On the next iteration it passed the NULL pointer to a receive call, causing an immediate crash.

Fix: The retry loop now acquires a fresh buffer before each attempt.

CVE-2026-82947 — Multiple Out-of-Bounds Reads in Frame Processing

SOEM version 2.0.0 and earlier contains multiple vulnerabilities in frame processing where a malicious device can cause the master to read data outside allocated buffers. The software uses length and offset values from device messages without validating them against buffer sizes. This can cause the master to access invalid memory locations, potentially disclosing sensitive information or causing crashes.
CVECVE-2026-82947
CWECWE-125 — Out-of-bounds Read
CWECWE-787 — Out-of-bounds Write
CWECWE-191 — Integer Underflow (Wrap or Wraparound)
CWECWE-129 — Improper Validation of Array Index

Affected Products

Fixed: CSAFPID-0002

Known Affected: CSAFPID-0001

Scores

  • CVSS 3.1: 7.1 (HIGH) — CVSS:3.1/AV:A/AC:L/PR:N/UI:N/S:U/C:H/I:N/A:L

Remediations

Vendor Fix: Upgrade to SOEM version 2.0.1 or later

Notes

Technical Details: In each affected code path, a length or offset value taken from an incoming frame or slave configuration is used directly to determine how much memory to read, without first checking that the value is within the bounds of the actual buffer. In the frame receive path, the offset of the working counter is not validated to be inside the buffer boundaries. In the cyclic mailbox handlers, the size used to read from and write to the slave's mailbox is taken from a slave-supplied configuration value without limiting it to the available buffer size. A slave that reports an oversized mailbox causes the read or write to extend into adjacent memory. This affects only applications that use the cyclic mailbox mode. In the EoE recv path, timestamp handling assumes buffer is large enough to contain a timestamp.

Fix: Each path was corrected by validating the relevant value against the actual buffer size before use. Frames or fragments that fail validation are discarded.
